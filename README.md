# tern-plugin-feishu · Tern 插件

让 omp 在指定 Workspace 中处理飞书消息，你在工作台看原消息、分析和依据、与 omp 对话、审核回复后发送。工作台发送按钮需要确认；omp 工具操作遵循项目的授权规则及审批策略。配色跟随 Tern 当前主题和明暗外观。

插件还保留了只读的 **飞书：查看 @我的消息** 面板，用于翻阅全部历史。

## 前置条件

- 支持 Luau 插件的 Tern。
- 官方 `@larksuite/cli`（`lark-cli`），已配置飞书应用并完成用户授权。
- `omp`，已配置好模型。工作台默认用 omp 的默认模型，可在设置里指定。

工作台需要这些用户权限：

| 用途 | 权限 | 缺少时 |
| --- | --- | --- |
| 检索消息和下载图片 | `search:message`、`im:message:readonly` | 无法使用 |
| 会话上下文 | `im:message.group_msg:get_as_user`、`im:message.p2p_msg:get_as_user` | agent 只看到触发消息 |
| 发送回复 | `im:message.send_as_user` | 发送失败并提示缺少的权限，其他功能正常 |
| 今日日程 | `calendar:calendar.event:read` | agent 不参考日程，并在界面标明「未授权」 |
| 过滤免打扰群（可选） | `im:chat.user_setting:read` | 开启过滤时提示错误，无法读取设置的群暂时隐藏 |

补充授权：

```sh
lark-cli auth login --scope "im:message.send_as_user calendar:calendar.event:read"
```

## 安装

在仓库目录执行：

```sh
tern plugin link .
```

修改后执行 `tern plugin reload tern-plugin-feishu`。重载会清空内存中的分析和本地会话，打开着的工作台会重新分析。

打开命令面板运行 **飞书：打开工作台**，或按 **Ctrl+Alt+Shift+F**。

从 Dock 启动的 Tern 不一定继承终端的 PATH。找不到命令时，用 **飞书：设置 lark-cli 路径** 和 **飞书：设置 omp 路径** 指定。npm 安装的 `lark-cli` 是依赖 `node` 的启动器，PATH 里没有 Node 时，指向 `<npm root -g 的输出>/@larksuite/cli/bin/lark-cli`。

### 布局与滚动

工作台按窗口的可用高度分配区块空间。切换消息、加载图片、生成分析或增加回复内容不会撑高整个页面；队列、活动日志、原消息、分析和回复区分别内部滚动，区块标题保留在边框上。

调整窗口大小时布局自动重排：宽窗口显示视图侧栏、队列和详情；中等宽度隐藏侧栏；窄窗口将队列和详情上下排列，并隐藏活动日志。窗口较矮时，原消息和分析左右并排。回复区的操作按钮固定在底部，不随回复内容滚动。设置页也可内部滚动。

## 设置

按 `,` 打开。`j` / `k` 移动，空格切换，`←` / `→` 换值，也可以用鼠标。

| 分组 | 内容 |
| --- | --- |
| Agent（omp） | 自动分析开关、并发数、打开时分析积压的条数、会话上下文条数、是否提供今日日程、是否把图片发给 omp、模型、思考强度、Workspace 目录、Skills 目录 |
| 消息来源 | @我、@所有人、私聊、星标联系人、隐藏机器人消息、过滤飞书免打扰／屏蔽群消息、按群名关键词忽略 |
| 运行 | 显示图片、自动刷新间隔、检索最近几天、发送前可撤销的秒数 |
| 会话规则 | `i`、`n` 添加的规则，可以切换或移除 |

要让某些群完全不经过 agent，用 `n` 或 `i`。这些会话也不会出现在其他消息发给 agent 的上下文里。关键词和来源开关是隐藏消息，隐藏的消息同样不会发给 agent。

队列会按消息的 `sender_type` 标注「用户」「机器人」或「身份未知」：`app`、`bot` 均识别为机器人，`user` 标注为用户，其余值或字段缺失标为未知。「消息来源 → 隐藏机器人消息」默认关闭，开启后从工作台队列隐藏机器人触发消息，关闭后恢复；不会修改飞书消息，也不会屏蔽用户或未知身份。此开关不清除其他消息会话历史中的机器人发言。「用户」仅表示账号身份，不保证由真人操作，暂不区分员工类型或数字员工。

「过滤飞书免打扰／屏蔽群消息」默认关闭。开启后，按飞书群个人设置 `is_muted` 隐藏该群所有来源的消息（包括 @我和星标联系人）；`is_mute_at_all` 仅隐藏该群的 @所有人 消息，私聊不受影响。每次刷新重新读取设置，退出设置页也会刷新；关闭开关可恢复被隐藏的消息，不会归档或修改飞书设置。过滤后的消息不会进入新的 omp 分析或其他消息的上下文，已经发给 omp 的内容无法撤回。此开关只作用于工作台，不影响只读的「查看 @我的消息」面板。

首次使用可能需要补充用户授权：`lark-cli auth login --scope "im:chat.user_setting:read"`。查询失败或某个群未返回设置时会显示错误，并暂时隐藏状态未知的群，避免将其误当作未免打扰。过滤以 OpenAPI 提供的上述两个字段为准，无法识别未通过它们暴露的客户端屏蔽状态。

### omp 工作目录与技能

- **Workspace 目录**：自动分析、`/` 对话、`o` 原生 omp 都从这里启动。留空使用插件数据目录；支持绝对路径和 `~/`，相对路径以插件数据目录为基准。
- **Skills 目录**：额外的技能根目录（其下放各技能的 `SKILL.md`），支持绝对路径、`~/` 或相对 Workspace 的路径。留空时完全沿用 omp 的项目和全局技能配置；显式填写时通过运行配置覆盖 `skills.customDirectories`，不强制开启被用户禁用的技能发现。项目也可在 `.omp/config.yml` 设置此项。
- 例如 Workspace 填 `~/work/project`，Skills 填 `.agents/skills`。两项在设置页 Agent 分组下方，可在分组内滚动查看。配置的 Workspace 不存在时，三个入口均回退到插件数据目录：工作台顶部和活动日志显示原路径、实际目录与跳过的技能配置，原生入口显示提示。不会创建失效的目录或清空你的设置；修复路径后，下次启动自动使用配置目录。
- 回退时跳过原 Workspace 的相对 Skills 路径，避免改以插件目录解析而误加载。独立配置的绝对路径或 `~/` 技能目录若存在则继续加载，不存在则跳过并提示；其余技能发现遵循回退目录及全局配置。Workspace 存在但不可读、路径是文件等错误仍会报错；Workspace 正常时，显式 Skills 路径无效也仍会报错。
- 保存后，下一次分析、对话或打开原生 omp 使用新设置；已启动的进程不会迁移。旧会话继续保留原来的聊天历史，换目录不会清除此前已经发给模型的上下文。
- 会话和临时启动配置仍保存在插件数据目录，使用绝对路径续接与清理，不会在 Workspace 中创建插件会话目录。
- 自动分析、`/` 和 `o` 均继承 omp 正常的项目指令（如 `AGENTS.md`）、规则、技能、扩展、MCP、工具及审批策略。插件不再限制内置工具、不禁用 MCP、不强制审批模式，也不添加自动批准参数。若项目策略要求交互确认，无头分析或对话可能被阻塞，应到原生 omp 继续，而不是绕过确认。
- **Workspace 不是文件访问沙箱。** 读取到的项目或技能内容可能被发送给模型，包括被消息诱导读取的内容；只配置你愿意让模型访问的环境。

插件任务提示词位于 `lib/agent.luau`：`WORKBENCH` 通过 `--append-system-prompt` 附加到默认系统提示词，不再替换它；`agent.analyze()` 将自动分析任务、消息上下文和 `ANALYSIS_FORMAT` 拼为本轮输入；`agent.converse()` 标识当前用户的直接请求并使用 `CHAT_FORMAT`，没有会话时同样附上消息上下文。消息上下文的 `trigger` 含 `message_id` 和 `chat_id`，`thread` 每条含 `id`，供技能精确查询；这些 ID 只是业务数据，不构成授权。工具可以正常调用，最终输出保留工作台需要的 JSON。项目业务约定放在 Workspace 的 `AGENTS.md` 和各技能的 `SKILL.md` 中，不应只修改插件提示词来配置业务操作。

## 和 omp 的关系

- **分析：** 每条消息一个独立的 omp 会话，无头运行。使用 Workspace 的正常配置主动查询和核验；不因消息里有人要求审批、发布等就认定当前用户授权。副作用需要符合可信项目策略的明确授权。
- **提示词不是沙箱：** 插件不再用工具白名单或 MCP 禁用列表隔离模型；项目或全局配置（包括 `yolo`、工具覆盖策略和扩展）可能允许自动执行操作。第三方消息是不可信业务数据，项目技能必须明确授权边界。不要加载不可信项目或扩展。
- **`/` 对话：** 用 `--resume` 续接同一个会话，使用相同目录、技能、工具和审批策略。用户直接授权的具体任务可以由工具执行；正常工具调用不再导致本轮结果被丢弃。最终答复包含实际结果及可选的新回复稿。
- **`o` 原生块：** 在配置的 Workspace 打开同一个会话并继承正常审批策略，用于继续交互、处理需要确认的工具调用。打开会话本身不授权新操作；原生块的结论不会自动变成工作台回复稿。

## 消息从哪里来

- 最近几天的 @我（含 @所有人）、私聊，以及星标联系人的消息。每个来源最多取一页 50 条，超过时界面会提示。
- 同一私聊的多条消息合并为一行，只回复最新一条。如果私聊的最新消息是你发的，这一行会自动移到已处理。
- 星标是插件自己的本地名单，与飞书客户端无关。
- 消息里的图片会下载并显示在原消息块里，点击可放大。卡片消息按 CLI 输出的文本显示。

## 安全与隐私

- **内容会发给模型。** 触发消息及其图片、会话近期消息、其他待处理消息摘要、日程，以及工具读取的项目文件和业务系统结果，可能通过 omp 发给模型服务商。使用前确认这符合组织的数据规定及实际模型配置。
- **工作台发送按钮需要确认。** 按 `a` 或点击「通过并发送」的插件发送路径保留等待撤销和重复发送保护。omp 直接使用工具执行审批、发布或发送等动作，不经过此按钮；授权约束来自项目指令、技能和工具审批策略，不能把按钮确认机制视为这些工具的安全屏障。
- **本地保存的内容：**
  - 长期保存：消息 ID、处理结果和时间、星标名单、设置和会话规则。
  - 临时保存：omp 会话和下载的图片包含消息内容，放在插件数据目录的 `sessions/` 和 `images/`。会话在消息发送或归档后的下一次刷新时删除；两个目录在插件加载时都会清空。
- **凭证由 `lark-cli` 和 omp 管理。** 插件不读取或存储 token。

## 费用

每次分析和对话都是一次模型调用，omp 上报的累计花费显示在「omp」block 里。打开工作台时按设置分析最新的积压消息，更早的消息在选中时才分析，之后新到的消息都会自动分析。

## 文件

- `plugin.toml`：插件与 block 声明。
- `window.luau`：命令面板入口、快捷键、路径设置和打开原生 omp 块。
- `host.luau`：只读的 @我 面板，并加载工作台。
- `lib/inbox.luau`：工作台状态、队列、分析调度和审核操作。
- `lib/view.luau`：工作台和设置页的界面。
- `lib/settings.luau`：设置项定义和读写。
- `lib/feishu.luau`：所有 `lark-cli` 调用。
- `lib/agent.luau`：提示词和所有 omp 调用。
- `lib/runtime.luau`：共用的 omp 工作目录、技能配置、绝对会话路径与原生命令引用。
- `lib/edit.luau`：输入框的文本编辑。
- `inbox.css`：终端样式，颜色全部取自 Tern 主题变量。

插件 API 参考：[Tern Plugin SDK](https://docs.stencil.so/tern/)。
