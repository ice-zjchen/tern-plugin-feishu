# tern-plugin-feishu · Tern 插件

让 AI 判断每条飞书消息该怎么处理：不用处理、回复即可，还是需要深入处理。回复稿由你复制到飞书发送；需要深入的，确认后开始任务，在新的任务页里去做。配色跟随 Tern 当前主题和明暗外观。

界面里只有两个说法：**AI** 指判断消息、写回复稿、回答 `/` 的分析助手；**任务**指确认后新开的任务页，在里面实际执行。两者底层都由 omp 运行，下文只在讲安装、配置和实现时提到 omp。

插件还保留了只读的 **飞书 Feishu / Lark：查看 @我的消息** 面板，用于翻阅全部历史。

工作台只初判；完整 CR、深入代码排查和开发确认后在目标 Workspace 的新任务页执行。任务说明第一行可写 `执行 Workspace：/absolute/repo`，与任务一起展示、编辑。启动器只读取确认后的任务首行，目录须在默认 Workspace 的 `workspaces.md` 表格第二列以反引号列出，并在启动时可读；无效时阻止启动，不回退执行。未指定则用默认 Workspace。指定其他目录时同时设置实际 `cwd` 和 `--cwd`，不传默认工作区的 `--config`，让目标目录发现自己的指令、技能和配置；任务交接头仍保留消息信任边界及 `<reply>` 约定。旧「附加仓库」任务须重新确认，已开的任务页不迁移。完整 CR 默认 fetch 而非 pull，不隐含修改代码、平台 approval 或 merge。

## 前置条件

- 支持 Luau 插件的 Tern。
- 官方 `@larksuite/cli`（`lark-cli`），已配置飞书应用并完成用户授权。
- `omp`，已配置好模型。工作台默认用 omp 的默认模型，可在设置里指定。

工作台需要这些用户权限：

| 用途 | 权限 | 缺少时 |
| --- | --- | --- |
| 检索消息和下载图片 | `search:message`、`im:message:readonly` | 无法使用 |
| 会话上下文 | `im:message.group_msg:get_as_user`、`im:message.p2p_msg:get_as_user` | AI 只看到触发消息 |
| 今日日程 | `calendar:calendar.event:read` | AI 不参考日程，并在界面标明「未授权」 |
| 过滤免打扰群（可选） | `im:chat.user_setting:read` | 开启过滤时提示错误，无法读取设置的群暂时隐藏 |

补充授权：

```sh
lark-cli auth login --scope "calendar:calendar.event:read"
```

## 安装

在仓库目录执行：

```sh
tern plugin link .
```

修改后执行 `tern plugin reload tern-plugin-feishu`。重载优先恢复本地消息快照、判断、草稿、对话和分析会话，不因重载重新获取消息或调用模型。首次没有快照时才自动获取；中断的分析标为失败，按 `r` 手动重试，不自动重放可能已执行过的操作。

打开命令面板，搜索「飞书」、`feishu` 或 `lark`，运行 **飞书 Feishu / Lark：打开工作台**，或按 **Ctrl+Alt+Shift+F**。查看消息和路径设置命令同样支持这些品牌词，英文搜索不区分大小写。

从 Dock 启动的 Tern 不一定继承终端的 PATH。找不到命令时，用 **飞书 Feishu / Lark：设置 lark-cli 路径** 和 **飞书 Feishu / Lark：设置 AI 程序路径**（即 `omp` 可执行文件）指定。npm 安装的 `lark-cli` 是依赖 `node` 的启动器，PATH 里没有 Node 时，指向 `<npm root -g 的输出>/@larksuite/cli/bin/lark-cli`。自动分析和 `/` 对话启动 omp 时，会把该路径所在目录、fnm 默认 Node、`~/.local/bin`、Homebrew 目录补进 PATH，让 omp 的工具也能运行 `lark-cli` 和 `node`。

### 消息时间

工作台队列、消息摘要和原始对话统一按本地自然日展示：今天为 `14:30`，昨天为 `昨天 14:30`，此前 2–6 天为 `周二 14:30`，更早的今年消息为 `10月28日 14:30`，往年消息为 `2025年10月28日 14:30`。悬停显示完整日期和时间；跨日不按过去 24 小时计算。只读历史检索面板仍保留完整日期。

旧快照中仅存时分的会话上下文会失效，下次查看或刷新时重新读取，不猜测日期；已保存的判断和草稿不受影响。

### 标签名

工作台标签以固定前缀 `飞书｜` 开头，后面是三个视图的条数，与工作台顶部的视图标签计数一致，用 `·` 分隔，如 `飞书｜待处理7·处理中2·稍后1`。条数为 0 的视图不显示，以免超出 Tern 标签名约 17 个汉字的宽度。全部为 0 时显示 `飞书｜已清空`，首次加载显示 `飞书｜加载中…`，一条消息都没能加载时显示 `飞书｜加载失败`。权限、刷新等问题只在工作台顶部说明，不在标签上标记。

### 处理流程

- **要回复：** `a` 把回复稿复制到剪贴板并跳到飞书会话，你粘贴发送，消息移到「处理中」显示“待你发送”。刷新后若检测到交接后的同会话发言，只显示“可能已回复”及命中内容；它可能是群里的其他话题，不自动算作处理完成。点击「确认这是我的回复」才进入「已处理」，确认后仍可按 `u` 撤销。
- **要深入：** 卡片标题为「需要深入处理」，中间显示可编辑任务说明，按 `a`（「开始任务」）确认后新开任务页。任务页标签名为 `飞书: <任务标题> · <发送者>@<群名>`（私聊只写发送者），过长时截断，标签统一标为蓝色；图标沿用 AI 会话自己的图标，因此用颜色区分飞书任务。按 `o` 手动开任务时用消息摘要代替任务标题。工作台和 @我的消息 标签分别显示收件箱和消息图标。如果 AI 认为对方要的是难以撤销或影响他人的动作（如通过发布单），卡片会写明这个动作，且只能点击「确认并开始任务」启动。这只是提醒，由模型判断，可能漏判，不是权限限制。任务以 `task:<消息 ID>` 保存，重载不丢；运行中按 `a`（「查看任务」）跳回已有任务页，不会重复新开。工具与副作用仍遵循项目和 omp 配置，不增加确认前的硬隔离。
- **本轮结束：** 任务的一轮结束不代表业务任务成功。这条回到「待处理」，显示“本轮结束 / 待确认”和任务里 AI 的原话。`a`（「回到任务继续」）回到任务页，确认无误后点「确认完成并归档」或按 `x`。任务等你回复、任务页被关闭时同样回到「待处理」并排在最前。如果结果包含 `<reply>回复正文</reply>`，消息回到「要回复」，仍需你去飞书发送。

### 发给任务的内容

初判写任务说明时，只有完成任务确实依赖原对话（如“按上面说的”、截图、讨论定下的结论）才写明要读哪条消息；链接、编号和事实已写全的任务不要求读群。

开始任务前会增加一轮 AI 判断，比较**最终确认的任务说明**与触发消息、已读取的聊天内容；手改任务或通过 `/` 调整后，以最终内容为准。此轮使用独立的临时会话，不继承初判里的其他待办、日程或对话；会增加一次分析的等待，费用计入工作台总费用。

- **弱关联：** 消息只是入口或契机，任务本身不依赖原对话。任务页只收到执行规则和任务说明，不附消息正文、会话信息或聊天记录。
- **强关联：** 原对话是任务的业务依据，例如需要核实目标、约束或“上面说的方案”。任务页附完整触发消息、`chat_id`、`message_id` 和消息时间，并提示使用飞书消息技能按需补读相关回复或前后聊天；任务信息足够时不额外查询。不再默认塞入最近聊天，也不按同群、同发送者扩大范围。

判断失败不会打开任务页，可再次开始；判断期间任务、消息或处理状态发生变化时，需重新确认。按 `o` 手动开任务时：保留触发消息及定位信息，等待你指示，不增加关联性判断。其他会话的待处理消息和日程只用于初判，不会发进任务。

### 分析记录

判断理由下方的「分析记录」默认折叠，标题行显示实际模型、目录和工具次数。展开后是这次分析调用过的工具，以及模型、思考强度、Workspace、Skills、发送范围、用时和费用。

这些来自 omp 的事件流，不是模型的自述。工具步骤只显示读取的路径、链接或工具自己标注的意图，不显示代码、命令和思考内容；它只记录最近一次分析，不含新开 tab 里的任务。旧版本分析的消息没有记录，会显示当前设置并注明不一定是当时用的。

### 连续 @ 合并

同一个人在同一个群里连续 @ 你时，合并成一条事项，队列显示“N 条”，所有 @ 你的消息都高亮：

- **还没处理：** 与上一条间隔 10 分钟内的并入。
- **已回复、待发送或已归档：** 30 分钟内再次 @ 你，并回原事项并放回「待处理」，标明“你回复后有新消息”或“归档后有新消息”。在「稍后」里的事项 10 分钟内再次 @ 你也会放回。
- **任务已在运行：** 只提示有新消息并放回「待处理」，不会自动发到任务里。群消息是第三方内容，要不要告诉任务由你决定。

新消息到达后约 90 秒内先不分析，等对话停下再判断一次。已判断过的事项继续用原来的分析会话，只发送上次之后的新消息。新判断出来前，旧回复稿和任务说明不能复制或启动，手动修改过的内容也会被新判断替换。

不同的人在同一个群 @ 你、@所有人、不在窗口内的消息，都仍是独立事项。私聊仍按会话折叠。

### 布局与滚动

顶部是处理阶段、分析状态、刷新与设置；左侧是来源筛选和两行一条的队列，底部入口查看可忽略的消息；中间是摘要和当前阶段的下一步，补充输入放在卡片里；右侧直接显示原始对话和判断理由，触发消息高亮，超过 4 条时可打开完整对话。底部只保留最近活动、撤销和快捷键，不再常驻星标侧栏与大块活动日志。

宽窗口三栏各自保持可用高度；中等宽度收起右栏，把触发消息常驻在卡片上方，判断理由可展开，完整对话在弹窗中查看；窄窗口将队列与详情上下排列，详情内部可滚动至任务操作和原消息，不靠撑高整页。所有颜色跟随 Tern 明暗主题。设置页仍按原有分组滚动。

## 设置

按 `,` 打开。`j` / `k` 移动，空格切换，`←` / `→` 换值，也可以用鼠标。

| 分组 | 内容 |
| --- | --- |
| AI 分析 | 自动分析开关、并发数、打开时分析积压的条数、会话上下文条数、是否提供今日日程、是否把图片发给 AI |
| 模型与目录 | 思考强度；初判、`/` 对话、交办前关联判断各自的模型（留空用 omp 默认模型，可填 `@smol` 这类角色）；Workspace 目录、Skills 目录 |
| 消息来源 | @我、私聊、星标联系人 |
| 过滤 | 隐藏 @所有人、隐藏机器人消息、隐藏免打扰的群、按群名隐藏 |
| 运行 | 显示图片、自动刷新间隔、检索最近几天 |
| 会话规则 | `i`、`n` 添加的规则，可以切换或移除 |

要让某些群完全不经过 AI，用 `n` 或 `i`。这些会话也不会出现在其他消息发给 AI 的上下文里。关键词和来源开关是隐藏消息，隐藏的消息同样不会发给 AI。

队列会按消息的 `sender_type` 标注「用户」「机器人」或「身份未知」：`app`、`bot` 均识别为机器人，`user` 标注为用户，其余值或字段缺失标为未知。「过滤 → 隐藏机器人消息」默认关闭，开启后从工作台队列隐藏机器人触发消息，关闭后恢复；不会修改飞书消息，也不会屏蔽用户或未知身份。此开关不清除其他消息会话历史中的机器人发言。「用户」仅表示账号身份，不保证由真人操作，暂不区分员工类型或数字员工。

「隐藏 @所有人」默认关闭。开启后隐藏所有 @所有人 的消息，包括星标联系人发的；同时 @我 的消息仍然显示。关闭后恢复，不会归档或修改飞书消息。隐藏的消息同样不会发给 omp。每个来源每次刷新只取最新一页 50 条，@所有人 也占名额；还有更早的消息时，队列底部会出现「加载更早」，范围不超过设置的回看天数。加载出来的消息不会自动分析，选中后才会排队。

「隐藏免打扰的群」默认关闭。开启后，按飞书群个人设置 `is_muted` 隐藏该群所有来源的消息（包括 @我和星标联系人）；`is_mute_at_all` 仅隐藏该群的 @所有人 消息，私聊不受影响。每次刷新重新读取设置，退出设置页也会刷新；关闭开关可恢复被隐藏的消息，不会归档或修改飞书设置。过滤后的消息不会进入新的 omp 分析或其他消息的上下文，已经发给 omp 的内容无法撤回。此开关只作用于工作台，不影响只读的「查看 @我的消息」面板。

首次使用可能需要补充用户授权：`lark-cli auth login --scope "im:chat.user_setting:read"`。查询失败或某个群未返回设置时会显示错误，并暂时隐藏状态未知的群，避免将其误当作未免打扰。过滤以 OpenAPI 提供的上述两个字段为准，无法识别未通过它们暴露的客户端屏蔽状态。

### 工作目录与技能

- **Workspace 目录**：自动分析、`/` 对话、任务页都从这里启动（任务首行指定了执行 Workspace 时除外）。留空使用插件数据目录；支持绝对路径和 `~/`，相对路径以插件数据目录为基准。
- **Skills 目录**：额外的技能根目录（其下放各技能的 `SKILL.md`），支持绝对路径、`~/` 或相对 Workspace 的路径。留空时完全沿用 omp 的项目和全局技能配置；显式填写时通过运行配置覆盖 `skills.customDirectories`，不强制开启被用户禁用的技能发现。项目也可在 `.omp/config.yml` 设置此项。
- 例如 Workspace 填 `~/work/project`，Skills 填 `.agents/skills`。两项在设置页「模型与目录」分组里，可在分组内滚动查看。配置的 Workspace 不存在时，三个入口均回退到插件数据目录：工作台顶部和活动日志显示原路径、实际目录与跳过的技能配置，任务页启动时显示提示。不会创建失效的目录或清空你的设置；修复路径后，下次启动自动使用配置目录。
- 回退时跳过原 Workspace 的相对 Skills 路径，避免改以插件目录解析而误加载。独立配置的绝对路径或 `~/` 技能目录若存在则继续加载，不存在则跳过并提示；其余技能发现遵循回退目录及全局配置。Workspace 存在但不可读、路径是文件等错误仍会报错；Workspace 正常时，显式 Skills 路径无效也仍会报错。
- 保存后，下一次分析、对话或开始任务使用新设置；已启动的进程不会迁移。旧会话继续保留原来的聊天历史，换目录不会清除此前已经发给模型的上下文。
- 会话和临时启动配置仍保存在插件数据目录，使用绝对路径续接与清理，不会在 Workspace 中创建插件会话目录。
- 自动分析、`/` 和任务页均继承 omp 正常的项目指令（如 `AGENTS.md`）、规则、技能、扩展、MCP、工具及审批策略。插件不再限制内置工具、不禁用 MCP、不强制审批模式，也不添加自动批准参数。若项目策略要求交互确认，无头分析或对话可能被阻塞，应按 `o` 手动开任务继续，而不是绕过确认。
- **Workspace 不是文件访问沙箱。** 读取到的项目或技能内容可能被发送给模型，包括被消息诱导读取的内容；只配置你愿意让模型访问的环境。

提示词在 `prompts/*.md`，每个文件用 `<!-- @名称 -->` 分成若干块，`{{变量}}` 由代码填入，缺变量或多给变量都会直接报错：`system.md` 通过 `--append-system-prompt` 附加到默认系统提示词；`analysis.md` 是初判；`chat.md` 是 `/` 对话；`relevance.md` 是交办前的关联判断；`task.md` 是新任务页的第一条消息。项目业务约定放在 Workspace 的 `AGENTS.md` 和各技能的 `SKILL.md` 中，插件不内置任何操作类型。

## 和 omp 的关系

- **分析：** 每条消息一个独立的 omp 会话，无头运行，只判断不动手。这条边界靠提示词约定，不是沙箱：omp 的工具和审批策略仍按你的配置。
- **`/` 对话：** 用 `--resume` 续接分析会话，同样只判断不动手。
- **新开 tab：** 普通的 omp 会话，在 Workspace 目录启动，保存在 omp 自己的会话目录，消息处理完也不会被清理。按你的 omp 配置运行，第一条消息发出后立刻开始，所以确认前要看一眼任务说明。

## 消息从哪里来

- 最近几天的 @我（含 @所有人）、私聊，以及星标联系人的消息。每个来源最多取一页 50 条，超过时界面会提示。
- 同一私聊的多条消息合并为一行，只回复最新一条。如果私聊的最新消息是你发的，这一行会自动移到已处理。
- 星标是插件自己的本地名单，与飞书客户端无关。
- 已读状态每次刷新从飞书读取，只读不写：`●` 表示未读（合并的私聊里任意一条未读即算未读），`?` 表示飞书无法确定或读取失败，已读不加标记。同优先级未读排在前面，积压消息也优先分析未读。
- 已读不等于已处理：在飞书看过的消息仍留在待审核，要在工作台处理。在工作台处理也不会让飞书变成已读，要清除飞书红点需按回车跳到飞书。
- 消息里的图片会下载并显示在原消息块里，点击可放大。卡片消息按 CLI 输出的文本显示。

## 安全与隐私

- **内容会发给模型。** 触发消息及其图片、会话近期消息、其他待处理消息摘要、日程，以及工具读取的项目文件和业务系统结果，可能通过 omp 发给模型服务商。使用前确认这符合组织的数据规定及实际模型配置。
- **工作台不替你发消息。** 回复由你在飞书发送。omp 工具执行的操作由任务说明、项目技能和你的 omp 配置决定。
- **本地保存的内容：**
  - 长期保存：消息 ID、处理结果和时间、星标名单、设置和会话规则；工作台快照另保留消息正文、已加载的会话上下文、判断、编辑后的草稿／任务、对话、选择位置及会话 ID，供重载恢复。快照位于插件数据目录的 KV 中，包含业务内容，不是仅保存 ID。
  - 处理完就删除：omp 任务（任务说明、消息上下文和结果），存在插件的 KV 中，消息归档或回复后的下一次刷新时删除；工作台快照里的处理记录仍保留，用于「已处理」视图。
  - 分析会话和下载的图片包含消息内容，放在插件数据目录的 `sessions/` 和 `images/`。不再在插件加载时清空；已处理消息的分析会话仍在后续刷新时按原规则清理，独立执行 tab 的会话由 omp 自己保存。
- **凭证由 `lark-cli` 和 omp 管理。** 插件不读取或存储 token。

## 费用

每次分析和对话都是一次模型调用，omp 上报的累计花费保留在本地快照中。首次无快照时按设置分析积压消息（同优先级未读在前，再按时间从新到旧）；后续打开或重载直接恢复，不重复分析已完成的消息。手动刷新或到达自动刷新间隔仍会获取新消息，并只为尚未分析的新消息启动分诊。重载中断的对话不会自动续跑，会保留用户输入并显示中断说明。

## 状态与恢复

每个事项分别保存分析阶段、处理去向和任务页状态；显示状态、下一步按钮和三个视图的计数都从同一套选择器推导。外部调用只返回带请求编号的事件，不直接改队列；迟到的线程、分析、对话和任务准备结果不能覆盖新状态。模型由 host 运行时持有，多工作台面板共享一个模型和持久化写入者。

快照自动从 v1 迁到 v2，保留消息、手改草稿、分析会话、原始对话、任务结果和撤销记录。迁移不启动模型或下载；重载时运行中的分析标为中断，必须手动重试，不自动重放。临时请求、计时器、界面句柄和图片 blob 不入库。损坏或未知版本明确报错，不把旧数据当成空队列覆盖。

## 文件

- `plugin.toml`：插件与 block 声明。
- `window.luau`：命令面板入口、快捷键、路径设置和打开原生 omp 块。
- `host.luau`：只读的 @我 面板，并加载工作台。
- `src/core/`：事项类型、状态推导、视图成员与计数、消息合并、事件更新及 v1→v2 快照迁移；不依赖 Tern。
- `src/app/host.luau`：工作台 block 的薄入口。
- `src/app/runtime.luau`：唯一的 host 副作用执行器；进程结果回到事件队列，统一管理刷新、任务同步与等待对话稳定的定时器。
- `src/app/fetch.luau`：身份、日程、分页检索与群设置的刷新工作流。
- `src/ui/`：队列、详情、原始对话、设置、布局等渲染模块，以及输入事件与控件 ID；只读模型快照，不读存储或调用服务。
- `src/shared/time.luau`：消息时间的自然日分层格式。
- `src/shared/text.luau`：输入框的文本编辑（UTF-16 光标）、截断和消息链接白名单。
- `src/shared/template.luau`、`src/services/prompts.luau`：提示词模板的解析、加载和填充。
- `src/shared/markup.luau`：消息里的图片、@所有人 标记解析。
- `src/shared/schema.luau`、`src/shared/settings.luau`：设置定义及其存取、旧版设置迁移。
- `src/shared/bridge.luau`：工作台（host）与任务页（window）之间的任务记录和链接约定。
- `src/services/lark.luau`：所有 `lark-cli` 调用，两个面板共用。
- `src/services/omp.luau`：无头 omp 调用，按用途（初判、对话、关联判断）选模型。
- `src/services/launch.luau`：omp 的可执行文件、工作目录、技能配置、PATH，以及任务首行的执行 Workspace 校验。
- `src/services/store.luau`：版本化工作台快照（合并 0.5 秒内的修改再写入；开始分析、对话或任务前立即写入）、消息处理结果的恢复索引和星标。
- `src/services/ai.luau`：初判、对话、关联判断的提示词组装与结果解析；`src/core/judgment.luau` 校验结构化结果。
- `inbox.css`：终端样式，颜色全部取自 Tern 主题变量。
- `scripts/check.sh`：编译、对不依赖 tern 的模块做严格类型检查、运行 `tests/`，需要 `brew install luau`。

插件 API 参考：[Tern Plugin SDK](https://docs.stencil.so/tern/)。
